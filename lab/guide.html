SMILE LAB · BROADCAST KIT

Wiring captures, alerts & sponsors into OBS

Everything in the lab runs on one honest principle: the HTML overlay is chrome, OBS owns the sources. A browser source is a sandboxed web page — it cannot reach into your camera or window captures. So every scene renders card frames with transparent holes at exact, documented coordinates, and your captures sit underneath, showing through. This guide gives you every coordinate, preset and switch. All numbers assume a 1920×1080 base canvas (the scenes letterbox-scale themselves to any other resolution).

01The one rule: layer order

Order in an OBS scene = order in the Sources panel. Top of the list renders on top. There is exactly one correct stack:

If a capture sits above the overlay it will cover the frames, chips and ticker — always keep the browser source first in the list.

02Quick start (per scene, ~3 minutes)

Add the browser source with the scene URL (see lab index) · Width 1920 · Height 1080 · tick “Shutdown source when not visible” OFF, “Refresh browser when scene becomes active” ON.
Open ?cal=1 (append to the URL) — the scene draws dashed outlines on every hole and prints a live slot sheet with exact X · Y · W · H values.
Add your captures below the overlay. For each hole: right-click source → Transform → Edit Transform → set Position X/Y and Size W/H from the slot sheet.
Ratio mismatch? Hold Alt (Opt on macOS) and drag the red crop handles — crop the capture to the hole's aspect. The hole is transparent, so anything outside the slot never shows.
Save the scene as a preset (“SMILE · STUDIO 2-CAM”, “SMILE · CINEMA”…). Switching layouts = switching OBS scenes; the overlay needs no touching. Remove ?cal=1 when done.

05Alert engine — spam-proof by design

Chat and tips arrive from multiple platforms at once, so the shared engine (assets/alert-engine.js) enforces hard limits:

What it does

Max 2 cards on screen (URL-tunable). Everything else waits in a queue of 12.

Queue full? Low-priority events (follows) are dropped first — tips and raids always survive.

Same person spams? Their repeats merge into one card with a ×N counter for 9s — no stack, no flood.

Auto-dismiss with a progress bar; cards exit cleanly and the queue pumps the next one.

Tune it with the URL

?amax=3 — max cards on screen (1–4)

?adur=9 — seconds per card (default 7)

?aq=16 — queue capacity (default 12)

?ademo=1 — demo loop for rehearsals

Keys: A one alert · Shift+A spam storm (6 fast — proves the cap) · X clear.

Platform badges (YouTube · Twitch · TikTok · X · Kick) color-code each event, wired for multiplatform streams.

08FAQ — the honest answers

Can one HTML file control my camera and window captures?
No — by design. OBS browser sources are sandboxed web pages; OBS itself composites camera/window/display captures. That's why the kit is built as chrome-with-holes: the overlay draws the brand, you place the captures underneath using the cal sheet. Setup is once per scene preset, then it's just scene switching in OBS.
My monitor isn't 1920×1080 — will it look wonky?
No. Every scene renders a 1920×1080 composition and letterbox-scales to the exact browser-source size with proportional fit — 4K, 1440p, 1366×768, anything. Keep the OBS source at 1920×1080 for a 1:1 pixel match, and the stream canvas can be any resolution: the whole composition scales as one unit.
What if my webcam is 4:3 but the hole is portrait?
The holes are transparent, so a mismatched capture simply never shows outside the slot. Set the slot size from the cal sheet, then Alt-drag the red handles to crop the capture to the hole's ratio. If you'd rather letterbox than crop, the scene backdrop is brand ink — not raw black — so bars look intentional.
Viewers spam alerts across YouTube + Twitch + TikTok — will it block the screen?
Never more than amax cards render, repeats from one person merge into a ×N counter, and the queue drops follows before tips. Run Shift+A (storm test) before you go live to watch it behave.
Full-screen segment — I don't want anything on screen.
That's CINEMA: one colossal aspect-locked card, a top-left watermark inside the frame, the permanent bottom ticker and lower-left alerts — nothing else. The island stays centered ≤50% width, expanding only when you press N to name what's showing. Cam stays optional above the content for translators/commentary (V).
